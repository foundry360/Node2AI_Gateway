# Foundry360 License Manager

Internal Foundry360 application for Enigma licensing and deployment provisioning.

**Foundry360 is the license issuer and provisioning authority. Enigma is the license verifier and enforcement point.**

This app must **not** be deployed into customer VPC or air-gapped Enigma environments.

## Quick start (Docker)

If your shell already exports Enigma gateway `POSTGRES_*` / `DATABASE_URL` variables, either unset them or rely on the `F360_LM_*` overrides in `.env` — Compose uses prefixed names so the gateway env cannot hijack this stack.

```bash
cd foundry360-license-manager
cp .env.example .env

# Mount vendor private signing key (never commit)
cp ~/.enigma-license-signing/enigma-lic-2026-09.private.jwk \
   ./secrets/enigma-license-private-key.jwk
chmod 600 ./secrets/enigma-license-private-key.jwk

docker compose up -d --build
```

Open: [http://localhost:3085](http://localhost:3085)

Seed passwords apply only when users are first created. After that, change passwords in the portal (header → **Change password**). Re-seeding does not reset existing passwords.


## Local development (optional Node)

```bash
cp .env.example .env
docker compose up -d postgres
npm install
npx prisma migrate deploy
npm run db:seed
npm run dev
```

## Operational lifecycle

1. Deploy Enigma
2. Retrieve Deployment ID (Enigma Admin → System → Deployment)
3. Register Deployment in Foundry360 License Manager
4. Create License (DRAFT)
5. Issue & Sign
6. Download `enigma.license`
7. Deliver license to customer
8. Customer installs via Enigma System → License
9. Enigma verifies signature + Deployment ID
10. License becomes ACTIVE

## Identifiers

- **Deployment ID** — UUID generated by the Enigma installation
- **License ID** — Foundry360 commercial entitlement (e.g. `ENIGMA-ACME-2026-001`)

They are distinct.
